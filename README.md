# GJF Site — Next.js + Admin პანელი

## რა არის ეს პროექტი

gjf.ge-ს ნავიგაციის სტრუქტურის (dropdown მენიუებით) მიხედვით აწყობილი საიტი,
რომელსაც აქვს ჩაშენებული, პაროლით დაცული admin პანელი (`/admin`) სიახლეების,
ღონისძიებებისა და კლუბების დასამატებლად/შესაცვლელად — კოდის შეხების გარეშე.

მონაცემები ინახება Supabase-ში (უფასო, ღრუბლოვანი Postgres ბაზა), რომ
Vercel-ზე განთავსების შემდეგაც რეალურად ინახებოდეს (ჩვეულებრივი ფაილი
Vercel-ის სერვერზე ცვლილებებს ვერ ინახავს).

## პირველადი გამართვა (ერთხელ კეთდება)

### 1. Supabase პროექტის შექმნა

1. შედი [supabase.com](https://supabase.com)-ზე, დარეგისტრირდი უფასოდ (GitHub-ით შეიძლება)
2. შექმენი ახალი პროექტი ("New Project")
3. პროექტის დაშბორდში გახსენი **SQL Editor → New query**
4. დააკოპირე ამ repo-ს ფაილის `supabase/migrations/supabase-schema.sql` მთელი შიგთავსი, ჩასვი და დააჭირე **Run**
   — ეს შექმნის ცხრილებს (news, events, clubs) და ჩაწერს საწყის მაგალითებს
5. გახსენი **Project Settings → API** — იქ დაინახავ სამ მნიშვნელობას, რომლებიც შემდეგ ნაბიჯში დაგჭირდება:
   - `Project URL`
   - `anon public` გასაღები
   - `service_role` გასაღები (⚠️ საიდუმლო — არავის გაუზიარო)

### 2. გარემოს ცვლადები

დააკოპირე `.env.local.example` → `.env.local` და შეავსე:

```
NEXT_PUBLIC_SUPABASE_URL=<Project URL>
NEXT_PUBLIC_SUPABASE_ANON_KEY=<anon public გასაღები>
SUPABASE_SERVICE_ROLE_KEY=<service_role გასაღები>
```

admin-ში შესვლა Supabase Auth-ით (ელფოსტა + პაროლი) ხდება — იხილე ქვემოთ
„პირველი admin მომხმარებლის შექმნა" (ან, თუ ეს სექცია არ არსებობს, Supabase
დაშბორდში **Authentication → Users → Add user**).

სურვილისამებრ, თუ საიტს არა-ნაგულისხმევ დომენზე დებ:

```
NEXT_PUBLIC_SITE_URL=https://gjf.ge
```

ეს გამოიყენება sitemap.xml/robots.txt/RSS/JSON-LD-ში აბსოლუტური ბმულებისთვის —
თუ არ დააყენებ, ნაგულისხმევად `https://gjf.ge` გამოიყენება.

### 3. გაშვება

```bash
npm install
npm run dev
```

გახსენი `http://localhost:3000` — საიტი; `http://localhost:3000/admin` — admin პანელი
(შეხვალ Supabase-ში შექმნილი admin მომხმარებლის ელფოსტა/პაროლით).

## Admin პანელით სარგებლობა

`/admin`-ზე შესვლის შემდეგ ხელმისაწვდომია:

- **სიახლეები** — დამატება/რედაქტირება/წაშლა (`/admin/news`)
- **ღონისძიებები** — დამატება/რედაქტირება/წაშლა, კატეგორია (საქართველო/საერთაშორისო) (`/admin/events`)
- **კლუბები** — დამატება/რედაქტირება/წაშლა (`/admin/clubs`)

ცვლილება ფორმაში დაუყოვნებლივ აისახება საჯარო საიტზეც (მაქსიმუმ 60 წამის დაყოვნებით,
რადგან გვერდები ქეშირდება სისწრაფისთვის).

## Vercel-ზე განთავსებისას

1. GitHub-ზე ატვირთე პროექტი (როგორც ადრე)
2. Vercel-ზე პროექტის დაკავშირებისას, **Environment Variables** სექციაში
   დაამატე იგივე ცვლადები, რაც `.env.local`-შია
3. Deploy — admin პანელი პირდაპირ საჯარო დომენზეც იმუშავებს (`gjf.ge/admin`)

## სტრუქტურა

- `lib/supabase.js` — Supabase კლიენტები (public + admin)
- `lib/queries.js` — საჯარო გვერდების მონაცემთა წაკითხვის ფუნქციები
- `supabase/migrations/` — ბაზის სქემა + საწყისი მონაცემები (იხ. იქაური README.md ისტორიისა და მომავალი პრაქტიკის შესახებ)
- `middleware.js` — `/admin`-ისა და `/api`-ის დაცვა (Supabase Auth სესია + MFA)
- `app/admin/` — admin პანელის გვერდები
- `app/api/` — CRUD API route-ები (მხოლოდ admin ფორმებისთვის)
- `app/teams/`, `app/federation/` და სხვ. — ჯერ კიდევ სტატიკური/placeholder გვერდები
  (მომავალში იგივე პატერნით შეიძლება Supabase-ზე გადაყვანა)

## შემდეგი ნაბიჯები

1. Placeholder გვერდებში (ფედერაცია, ისტორია და ა.შ.) ტექსტის დამატება.
2. საჭიროების შემთხვევაში — Teams/Results-საც იგივე admin-CRUD პატერნის დამატება.
3. sitemap.xml, SEO მეტამონაცემები.
4. judomanager.com-ის რეალური ბმულები.
5. gjf.ge დომენის მიბმა Vercel-ზე.

## დამატებით: გვერდების ტექსტი და ნაკრების შემადგენლობა

Admin-ში ახლა ასევე არის:

- **გვერდების ტექსტი** (`/admin/pages`) — ფედერაციისა და ისტორიის ქვე-გვერდების
  (შემადგენლობა, აღმასკომი, წესდება, ისტორია და ა.შ.) ტექსტის რედაქტირება
- **ნაკრების შემადგენლობა** (`/admin/team-members`) — უფროსების/ახალგაზრდების/
  ჭაბუკების/ქალების როსტერის მართვა (წონითი კატეგორია + სახელი)

ეს ორივე ცხრილი (`pages`, `team_members`) ემატება `supabase/migrations/supabase-schema.sql`-ის
ბოლოში — თუ ბაზა უკვე შექმენი, საკმარისია ამ ახალი ნაწილის ცალკე გაშვება
Supabase SQL Editor-ში.

## PDF ატვირთვის გამართვა (Storage)

`pages`-ის ჩანაწერებზე (ფედერაცია/ისტორია) ახლა შესაძლებელია PDF-ის ატვირთვა
(მაგ. წესდების დოკუმენტი). ამისთვის საჭიროა Supabase-ში Storage bucket-ის
ერთჯერადი შექმნა:

1. Supabase დაშბორდში, მარცხენა მენიუში → **Storage**
2. **New bucket**
3. სახელი ზუსტად: `documents`
4. ჩართე **Public bucket** (რომ ატვირთული PDF-ები საჯაროდ ხელმისაწვდომი იყოს)
5. **Create bucket**

ასევე საჭიროა `supabase/migrations/supabase-schema.sql`-ის ბოლო ნაწილის (`file_url`, `file_name`
სვეტების დამატება `pages` ცხრილში) ხელახლა გაშვება SQL Editor-ში, თუ ბაზა
ადრე შექმენი.

admin-ში, გვერდის რედაქტირებისას, ახლა "დანართი (PDF)" ველი გამოჩნდება —
ატვირთვის შემდეგ საჯარო გვერდზეც ჩნდება ჩამოსატვირთი ღილაკი.

## მთავარი გვერდის Carousel

მთავარ გვერდზე ტოპში ახლა 5 უახლესი სიახლის carousel-ია — 5 წამში ერთხელ
ავტომატურად იცვლება (მაუსის მიტანისას ჩერდება), წერტილებით ქვემოთ ხელითაც
შეგიძლია გადართო.

**რომ სწორად გამოჩნდეს, ყველა სიახლეს სჭირდება ფოტო**: admin-ში
სიახლის დამატება/რედაქტირებისას ახლა "ფოტო" ველი სავალდებულოა
(`/admin/news`). თუ ფოტო არ აქვს, carousel-ში მუქი placeholder ფონი
გამოჩნდება ტექსტის ნაცვლად რეალური სურათის.

ფოტოს ატვირთვაც იმავე Storage bucket-ს იყენებს (`documents`), რაც PDF-ების
ატვირთვას — თუ ის უკვე შექმენი, დამატებით არაფერია საჭირო. ასევე
`supabase/migrations/supabase-schema.sql`-ის ბოლოში დამატებულია:
```sql
alter table news add column image_url text;
```
ეს ცალკე უნდა გაუშვა SQL Editor-ში, თუ ბაზა ადრე შექმენი.

## პროექტები (Federation Projects)

`/federation/projects` ახლა დინამიური სექციაა (არა სტატიკური ტექსტი) —
`/admin/projects`-იდან იმართება, სრული CRUD-ით (დამატება/რედაქტირება/წაშლა,
ფოტო + PDF დანართის ატვირთვის შესაძლებლობით).

**საწყისი მონაცემები** — 6 რეალური პროექტი, წამოღებული gjf.ge-ს ძველი
საიტიდან (სათაურები, აღწერები, დოკუმენტების ბმულები) უკვე ჩადებულია
`supabase/migrations/supabase-schema.sql`-ში.

**რომ ამუშავდეს**, საჭიროა SQL-ის ბოლო ნაწილის გაშვება (თუ ბაზა ადრე
შექმენი) — ეს ქმნის `projects` ცხრილს, ტვირთავს საწყის მონაცემებს, და
შლის ძველ placeholder-ს `pages` ცხრილიდან.

**მთავარ გვერდზე** კალენდრის ქვემოთ ახლა ჩანს "მიმდინარე პროექტები" —
5 უახლესი პროექტი, ჰორიზონტალურად სქროლვადი ბარათებით და ისრებით.

**ატვირთვისთვის** იმავე `documents` Storage bucket-ს იყენებს, რაც
სიახლეებისა და გვერდების ფოტო/PDF ატვირთვას — დამატებითი გამართვა არ
სჭირდება, თუ ის უკვე შექმენი.

## შედეგები, გალერეა, კონტაქტი — admin-იდან

ეს იყო ბოლო 3 გვერდი, რომელიც ჯერ სტატიკური იყო — ახლა ესეც admin-იდან იმართება:

- **`/admin/results`** — შედეგები (კატეგორია: საქართველო/საერთაშორისო, ასაკობრივი ჯგუფი: უფროსები/ახალგაზრდები/ჭაბუკები)
- **`/admin/gallery`** — ფოტო და ვიდეო გალერეა ერთად (ტიპის მიხედვით)
- **კონტაქტის ინფორმაცია** — `/admin/pages`-შივეა (`მისამართი`, `ელფოსტა`, `სოც. ქსელები`)

**რომ ამუშავდეს** — ახალი SQL ფაილი `supabase/migrations/supabase-schema-results-gallery-contact.sql`,
დააკოპირე მთლიანად და გაუშვი SQL Editor-ში.

ამის შემდეგ, ჰედერის ნავიგაციაში absolut ყველა გვერდი (გარდა "მთავარი"სა
და უბრალო ინფორმაციული ბმულებისა) admin-იდან იმართება.
